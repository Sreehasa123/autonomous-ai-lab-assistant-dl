1. Executive Summary & Main Objective

In academic institutions, students frequently struggle when conducting Deep Learning (DL) laboratory experiments. While high-level concepts are taught in lectures, hands-on implementation presents steep barriers:

  • Dataset Ambiguity: Students don't know which dataset suits their problem statement or what realistic accuracy to expect.
  • Data Leakage Traps: Fitting scalers/imputers before train/test splitting or augmenting test sets.
  • Catastrophic PyTorch Mismatches: Placing nn.Softmax() before nn.CrossEntropyLoss(), causing double-softmaxed, severely flattened gradients.
  • Training Instabilities: Exploding gradients (Loss is NaN), missing optimizer.zero_grad(), or improper learning rates.
  • Accuracy Paradox: Believing a 95% accuracy model on an imbalanced dataset is successful when it merely predicts the majority class.
  • Lab Report Writing Overhead: Spending hours manually drafting and formatting IEEE-style reports with LaTeX equations.
Main Objective: To develop an autonomous, pedagogical, RAG-guided multi-agent AI assistant that coaches students step-by-step through their deep learning experiments—from dataset discovery with expected accuracy targets to data preprocessing, architecture design, code synthesis, real-time error debugging, experiment history storage, and publication-ready academic report generation.

3. Technology Stack Breakdown

  • Streamlit 1.32+ Frontend UI: Python-native reactive dashboard with tabs, dynamic metric cards, and clean forms.
  • Google Gemini 3.8 Flash Generative Engine: Low-latency LLM with 1M token context for dataset reasoning, code generation, error diagnosis, and report writing.
  • RAG Architecture Grounding Engine: In-memory domain knowledge base preventing hallucination and enabling offline advice.
  • PyTorch & Torchvision Deep Learning Core: Modular nn.Module architectures, transfer learning (ResNet-18), and data augmentations.

  • JSON Persistence Local Storage: Lightweight local file database in workspace/experiments_history.json.

5. The 6 Deep Learning Lab Steps Explained

  1. Step 1: Dataset & Problem Setup: Analyzes problem title and aim, recommends datasets with expected student accuracy benchmarks, and auto-populates the workspace.
  2. Step 2: Preprocessing & Leakage Checker: Verifies scaling is fitted only on training data (prevents data leakage) and checks augmentations.
  3. Step 3: Model Architecture & Loss: Recommends appropriate backbones and verifies logits are passed directly to CrossEntropyLoss.
  4. Step 4: Training & Hyperparameter Tuning: Recommends gradient clipping, AdamW, early stopping, and schedulers.
  5. Step 5: Evaluation & Error Analysis: Recommends task-specific metrics (Macro-F1, Confusion Matrix) and diagnoses overfitting vs underfitting from loss curves.
  6. Step 6: Lab Report Generator: Consolidates the complete experiment into an academic report.

6. Comprehensive Metric Guide

Metric Formula Why It Matters in Deep Learning Labs
Accuracy (TP + TN) / Total Overall benchmark for balanced datasets. Misleading when classes are skewed.
Validation Loss -∑ y_i log(ŷ_i) Monitors generalization during training. Rising validation loss signals overfitting.
Macro-F1 Score Average of F1 across all classes Essential for imbalanced datasets; ensures minority classes aren't ignored.
Precision TP / (TP + FP) Penalizes False Positives (vital in spam detection, fraud detection).
Recall / Sensitivity TP / (TP + FN) Penalizes False Negatives (vital in medical diagnosis / disease screening).
Confusion Matrix 2D Contingency Table Identifies which exact pairs of classes the model confuses.
PR-AUC Area under PR curve The most informative metric when positive cases make up <5% of samples.

8. Project Viva / Presentation Cheat Sheet

Q: What is the main objective of this project?
A: To develop an autonomous, pedagogical, RAG-guided multi-agent AI assistant that coaches students step-by-step through their deep learning experiments—from dataset discovery with expected accuracy targets to data preprocessing, architecture design, code synthesis, real-time error debugging, experiment history storage, and publication-ready academic report generation.

Q: Why use RAG instead of standard ChatGPT?
A: Standard LLMs hallucinate subtle deep learning traps (like double Softmax) and provide disconnected answers without lab context. Our RAG engine grounds responses in verified deep learning rules and works even in offline mode.
